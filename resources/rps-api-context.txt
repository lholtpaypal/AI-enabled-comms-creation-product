Profile Attributes

Steps to Test

Check if the metadata for the attributes your using are available on staging. Following are the ways to verify the same.

Using the Portal:

https://www.msmaster.qa.paypal.com/campaigninsights/segments/attributes. Search for the attribute you want to use and make sure the same is available.

If the attribute is not available, please reach out to DL-PP-rps-platform-dev for help.

Update Attributes API:

If you intend to update attributes into RPS using the API, following are the API details for the same:

Update Attributes



METHOD: POST
URL: https://msmaster.qa.paypal.com:14751/rpsreadserv/v1/profile-attributes
HEADERS: Content-Type : application/json
REQUEST:
{
  "cust_id": "12047829602241376831", //Account number of the user
  "profile_attributes": [
    {
      "long_name": "account_creation_channel", //name of the attribute.
      "value": "TESLA"
    },
    {
      "long_name": "acct_cre_dt",
      "value": "2016-12-10"
    }
  ]
}
RESPONSE: [STATUS CODE: 200 for successful Update and 400 for a validation error]
NOTE: If you need help with getting the name of the attribute you should pass in the above request, please reach out to our team. The same also maps to the "System Name" in the below section on Segmentation Portal. Double click and copy the system name from the portal

API to evaluate if a user belong to a dynamic segment:

Generic API to evaluate both dynamic segments and customer lists.

This is a generic evaluate end point, where you can pass either customer list codes or dynamic segment codes and

evaluate if a given user is a part of the same. This API gives you the capability to use the same API to evaluate against

segments or lists, without having to differentiate the same.

Generic Evaluate End Point



METHOD: POST
HEADERS: Content-Type : application/json
URL: https://msmaster.qa.paypal.com:20068/v1/dynsegmentationserv/evaluate 
REQUEST:
{
  "id_type": "ACCOUNT_NUMBER",
  "id": "1617082364825547238",
  "segment_codes": [
    "acct_creation_channel_hermes",
    "NA_20170922_Ravi_Test_DS",
    "NA_20170922_Ravi_Test_CL",
    "DUMMY"
  ]
}
NOTE: For encrypted account number based evaluation use id_type as ENCRYPTED_ACCOUNT_NUMBER 
	  For cookie id or fpti id based evaluation use id_type as COOKIE_ID
RESPONSE: [STATUS CODE: 200]
{
  "id_type": "ACCOUNT_NUMBER",
  "id": "1617082364825547238",
  "segment_codes": [
    "NA_20170922_Ravi_Test_DS",
    "NA_20170922_Ravi_Test_CL"
  ]
}
