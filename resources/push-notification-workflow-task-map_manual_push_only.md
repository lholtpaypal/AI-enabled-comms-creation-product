# Push Notification Campaign Package — Task Map

**Scope:** Batch push, **push-only**, **one-off send**. (Channel decision and send-type decision are pre-resolved by this scope; event-based / triggered-campaign tasks are out of scope.)

Columns: the **task**, the **context needed to complete it** (tools, prompts, resources — left blank where the context is user-supplied and not something I can specify), and **who completes the task** (user or model).

> Legal review spans several steps: a **model pre-screen** (automated triage), the **submission prep** (population count, PDF asset), the **legal-ticket submission** in Quickbase, and the **final review/sign-off** owned by the user.

> Rows 1–7 below are your originals (text unchanged); the rest are the tasks/decisions needed to complete an end-to-end one-off batch push, drawn from the App Communications Playbook, the legal-ticket guide, and the CommsHub FAQ. "Who completes" and context are left blank where the source material doesn't specify them.

| # | Task | Context needed to complete task (tools / prompts / resources) | Who completes task |
|---|------|----------------------------------------------------------------|--------------------|
| 1 | **Declared Intent** — user states the campaign goal in the intent box, kicking off the flow. | — | **User** |
| 2 | **Generate Copy** — model generates the push copy once from the declared intent and displays it in an editable box. | **Tool:** `content-writer-agent` (LLM completion)<br>**Prompt:** system prompt for persuasive, marketer-grade copy + few-shot title/body examples<br>**Resources:** push-notification character limits, brand/tone guidelines | **Model** |
| 3 | **A/B Content Variants** — generates 2 extra Title/Body variants and renders 3 notification mock-ups. | **Tool:** `content-writer-agent`<br>**Prompt:** generate diverse variants; **constraint:** vary Title + Body only<br>**Resources:** original declared intent, output schema `{title, body}`, diversity instruction | **Model** |
| 4 | **Select Final Copy** — choose the winning Title/Body to launch from the generated options. | **Resource:** generated copy + A/B variants (rows above); push engagement bar (> 5% CTR) as a selection guide | **User** |
| 5 | **Select / Create Image Asset** — decide whether to include an image/icon and choose or upload the visual asset for the push. | **Resource:** can use PDS standard icon components or upload an image directly (per notification setup notes); push layout/content guide | |
| 6 | **Deeplink Search** — finds the in-app destination the notification should open and attaches it. | **Tool:** deeplink registry/catalog search API + resolver/validator<br>**Prompt:** map intent → destination screen → deeplink URI<br>**Resources:** deeplink catalog & schema, valid URI patterns, naming conventions, fallback rules | **Model** |
| 7 | **Audience (RPS Search Agent)** — forms the RPS API call, shows the terms it chose, returns Segment ID + Details. | **Tool:** RPS Search API (segment query + lookup-by-ID)<br>**Prompt:** translate intent (e.g., "eligible for PayPal Debit Card") into RPS query terms<br>**Resources:** RPS segment schema, eligibility-criteria taxonomy, product → eligibility-attribute mapping | **Model** |
| 8 | **Suggested Audience Options** — surfaces 2 ranked alternative segments; selection updates the audience boxes. | **Tool:** RPS Search API (candidate/alternative segments)<br>**Prompt:** produce ranked alternatives relevant to the intent<br>**Resources:** catalog of available segments + relevance ranking; current intent + selected segment | **Model** |
| 9 | **Set Up the Audience in RPS** — create the one-off audience: upload a customer list to RPS, or define a segment from existing RPS attributes. Define suppression rules. | **Tool:** go/segmentationportal (RPS)<br>**Resource:** App Communications Playbook Step 2 (one-off sends); new RPS attributes → #help-rps | **User** |
| 10 | **Set Schedule & Send Window** — choose the target launch date and delivery window for the one-off send. | **Resource:** target launch date is a required field on the legal ticket; time-of-day delivery windows (Delivery Intelligence, Q1'26) | **User** |
| 11 | **Configure the Push in CommsHub / Personalization Studio** — build the interaction: attach final copy, image, audience, and schedule, and populate the `oslo_deeplink` field. | **Tool:** go/pstudio<br>**Resource:** App Communications Playbook Step 3 (Push Process); Oslo navigation requires `oslo_deeplink` populated; use V2 universal links (`https://www.paypal.com/mobile-app/*`) — V1 deprecated (CommsHub FAQ §2; Notification gap-fill notes) | **User** |
| 12 | **Localization** *(if multi-locale)* — configure localized Title/Body for each target locale. | **Resource:** PStudio uses *account* language, not device language; confirm content changes when each locale is selected (CommsHub FAQ §4) | |
| 13 | **Legal Review Pre-screen** — automated compliance triage of the assembled package. | **Tool:** compliance/policy retrieval (RAG over legal playbook + applicable regs) + severity classification<br>**Prompt:** review against playbook, rate severity, output flags + suggested fixes + verdict (pass / needs-review / blocked)<br>**Resources:** marketing legal playbook, approved-claims library, prohibited-terms list, required-disclosure rules, escalation criteria | **Model** |
| 14 | **Pull Population Count from RPS** — retrieve the audience size for the legal ticket using the segment ID. | **Tool:** RPS portal<br>**Resource:** required field on the legal ticket (legal-ticket guide, "Before you start") | **User** |
| 15 | **Prepare Legal Asset (PDF)** — assemble notification copy, send logic, and suppression rules into a single PDF for legal. | **Resource:** legal-ticket guide — asset must be a PDF; include full copy + send logic + suppression rules; Asset Type = Initial Asset (or Revised Asset on resubmission) | **User** |
| 16 | **Submit Legal Ticket (Quickbase)** — create the request, attach the asset, and hit **Send** to move it into the active review queue. | **Tool:** Quickbase (legal-request app)<br>**Resource:** legal-ticket guide — 6-digit Kanban code, region/country, submission type/channel/frequency, Target Audience = Consumer, Overview (segment + behavior trigger + value prop), legal response date ≥ 3 business days out (excluding weekends/holidays) | **User** |
| 17 | **Final Legal Review** — reviews the pre-screen output, resolves flags, and signs off before launch. | — | **User** |
| 18 | **Test in Stage Environment** — validate the configured notification on Stage before production. | **Tool:** Stage (`api.stage2d0014` preferred for push)<br>**Resource:** CommsHub FAQ §8 push-testing setup; My Access roles work only in Prod — use go/personalization-qa for Stage | **User** |
| 19 | **Test / Validate Deeplink Navigation** — confirm the deeplink opens the correct in-app page on iOS and Android. | **Resource:** `oslo_deeplinks` are backfilled in Production only (not Stage) — copy manually for Stage testing; verify iOS vs Android parameter names; check the Android/iOS deeplink catalogs (CommsHub FAQ §11) | **User** |
| 20 | **Touchpoint Owner Approval** — touchpoint owners review and approve the interaction. | **Resource:** CommsHub FAQ §7.1 — touchpoint approvals (e.g., Venu Madhav, Blake Collard); request via #help-communication if urgent; required even for `oslo_deeplink`-only updates | Touchpoint owners |
| 21 | **ECM-ops Approval & Publish to Production** — obtain ECM-ops sign-off and publish the interaction live. | **Resource:** CommsHub FAQ §7.2 — ECM-ops approval + touchpoint approval + testing documentation required to publish to Production | ECM-ops |
| 22 | **Smoke Test to 5k Users** — run the required smoke test to 5,000 users before any ramp. | **Resource:** App Communications Playbook Step 4 / GTM — all new notifications must smoke-test to 5k users and exceed thresholds prior to ramp | **User** |
| 23 | **Evaluate Against Performance Thresholds** *(decision)* — decide whether smoke-test results clear the bar to ramp. | **Resource:** Push thresholds — Engagement > 5% CTR, Quality < 0.5% push opt-outs. App Communications Playbook GTM | **User** |
| 24 | **Ramp / Full Launch** *(decision)* — ramp the send to the full audience once thresholds are met. | **Resource:** App Communications Playbook Step 4 (ramp after passing smoke test) | **User** |
| 25 | **Launch & Monitor Performance** — track live performance on the push dashboard post-launch. | **Tool:** go/pushdashboard<br>**Resource:** monitor CTR, dismissals, and opt-outs against thresholds | **User** |
